## Fixture, evidence and cleanup policy

- Unique18-hex run ID per isolated dataset; example.invalid emails only, no real users/credentials. Out-of-band seed manifest stores expected collections/IDs/types/relationships/snapshot revision/hash/purpose, not secret values. Strict schemas must not gain an unrecognized runId/test field. Server-generated document IDs are recorded from acknowledgements and ownership relationships; a prefix is not proof of ownership.
- Reject pre-existing-ID/canonical identity collisions; never overwrite, merge or adopt an existing record. Current G1 recipe dates/hash placeholders need reviewed real-schema seeders and relative clocks. Only approved synthetic owners/inventory/historical claims may be used. Retain original/after mutation receipts and independently validate audit/inventory/references.
- OTP/JWT/QR/passwords, request/response bodies, credential URI and raw exceptions stay out of artifacts; transient synthetic secrets only in memory. Evidence contains hashes, typed codes/status counts, approved nonsecret synthetic IDs/revisions, invariants, resource totals and owned-handle close outcome.
- Default is **no database deletion**. Existing cleanup() throws and cleanupPlan cannot execute. A future cleanup grant must name database/collection/exact acknowledged IDs/current state or revision and maximum count, exclude pre-existing/shared/unowned rows, verify connected target immediately beforehand and archive required audit/evidence. It requires separately reviewed code and explicit approval, never an automatic finally delete. No cleanup command is proposed in this plan.
- Rollback of business mutations uses reconciliation/quarantine or an expressly reviewed CAS compensating action, not raw snapshot overwrite. Do not revive consumed challenges, lower versions, erase attempts, reissue decisions or re-pend redeemed records. Do not claim a timed-out transaction rolled back until actual outcome is reconciled.
