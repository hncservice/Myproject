# Phase C source-only authentication rollout review

This phase adds optional User metadata for tokenVersion/isActive, OTP issuance time/window/count and verification attempts. No existing records, indexes or databases are read/backfilled; no schema migration script is run. Missing legacy tokenVersion is interpreted as zero, isActive as enabled, and missing OTP counters as zero. Existing customer JWTs without version/type remain accepted only while the stored version is zero; explicit non-user types never authenticate as customers.

New challenges bind pending registration changes in the same conditional update as their hash. Issuance compares the original hash/request time/account version; verification reserves one of five attempts atomically and consumes the original challenge/expiry/pending details conditionally. Existing valid legacy challenges can be consumed under the same limits. New customer phone writes are canonical Qatar numbers; reads check bare digits and common +974 spellings. Historical unusual whitespace aliases/admin write paths still need a separate conflict/migration review; email/phone uniqueness is not proof of one physical person or phone ownership.

Before any runtime rollout: coordinate all authentication instances, drain old workers/challenges, confirm restricted sandbox index/conditional-update behavior under separate permission, and test new/old-token compatibility with synthetic accounts. Old instances that ignore counters or tokenVersion must not remain in service after revocations. Two additive handlers are declared: POST /api/auth/resend-otp and POST /api/auth/logout. The five existing auth endpoints and their middleware retain their contracts/order. No gameplay/experimental route, provider mounting, backend startup, SMTP verification or credential creation occurs here.

Logout revokes all tokens for the selected account by conditional version increment. Browser sign-out clears local state even if the revocation request fails; the UI must report that server revocation was not confirmed. A replayed revoked token cannot revoke a newer login. Delivery failure keeps the reserved cooldown/send budget and pending registration so the owner can retry; do not claim exactly-once SMTP delivery or retain plaintext OTPs for retries.

Rollback: preserve version/counter fields and audit evidence; do not restore a server that accepts revoked JWT versions until their maximum lifetime has elapsed or a reviewed equivalent gate is retained. Do not decrement versions, reset users/prizes, or backfill live records as a rollback. Field defaults do not prove deployed DB behavior. No launch/production readiness is asserted.
