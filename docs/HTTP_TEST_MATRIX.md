## Final handover — database middleware ordering and mitigation decision

F02 (High), affected server/server.js sections7–9, config/db.js and auth/rate-limit middleware. The source declares CORS/Helmet/logging/parsers first, then root/health, then app.use('/api', lazyDB), then the five original business mounts. Protected account guards and the auth-route IP limiters run inside those later routers. Therefore an unauthenticated GET /api/admin/vendors, /api/unknown or an unauthenticated public login/register request can initiate a DB connection before rejection. Missing Origin is allowed by design; authentication is not provided by CORS. Health/root return earlier. The promise coalesces concurrent attempts within one app instance but resets on rejection; later failures can reconnect repeatedly, and separate instances each have a promise. A resolved promise is not explicitly invalidated on later disconnection. The configured URI is unrestricted by the production connector.

Five new offline cases include development/production redaction and three connection-gate characterizations. Fake-port tests directly invoke the saved middleware: unauthenticated request causes one fake connection before next; two sequential failures cause two fake attempts and503 with existing safe body; simultaneous requests share one pending fake promise. No socket, actual Express dispatch, dotenv file or MongoDB connection is involved.

Proposed two-stage, fail-closed mitigation (NOT IMPLEMENTED):

1. Lowest-contract-impact step: a dependency-injected connection manager retaining single-flight semantics, with bounded waiters, bounded outage backoff/circuit state, and explicit handling of readyState/disconnection. On unavailable/backoff state return the same503 {success:false,message:'Database connection unavailable'}; never route a protected request without a ready connection/account checks. Public auth still legitimately needs DB. Root/health, request parsers, five API groups, role guards, response bodies and successful paths stay unchanged. Prove all clock/retry/disconnect/concurrent cases using fake ports first, then real driver/HTTP cases in the approved sandbox. This limits attempt amplification; it cannot promise zero unauthenticated connection attempts.
2. Optional protected-route preflight: separate cryptographic bearer/type/id validation (no model query) before connection acquisition, followed by unchanged DB-backed account/version/active checks and transactional fences. Never move the complete authUser/authVendor/authAdmin ahead of DB as-is: they query models. Never globally require a token for register/login/OTP/public wheel routes, trust Origin as auth, skip revocation after preflight, or accept client-provided prevalidation. Classify methods/routes using the actual Express routing policy and test case sensitivity, trailing/encoded paths, unknown methods, missing/forged/wrong-role/revoked tokens and public endpoints. Cache no cross-request authorization. Add a reviewed ingress/connection budget before DB; per-process memory limits alone do not solve distributed traffic.

Compatibility limit: preflight would intentionally change some DB-outage precedence from503 to401/403 and must be explicitly accepted if selected. Blanket middleware reorder or route classification based only on string prefixes is not proven safe. Current source-emulated routers cannot establish real Express matching, parser, JWT/account or driver behavior; unauthorized/public auth cannot all become connection-free while preserving functionality. Thus the user's implementation condition (offline proof of unchanged route/auth behavior) is not satisfied for a runtime reorder. **No startup, middleware ordering, route or auth implementation was changed in this handover.** Full-dispatch/driver proof and selected mitigation remain Phase G gates, not a claim that risk is fixed.

All H01–H28 tests remain proposed for actual HTTP; F01–F19 in PHASE_F_ISSUE_REGISTER.md provide severity, exact affected modules, correction, test requirements and authorization status. Separate execution/rollback plan: PHASE_G_SANDBOX_PLAN.md.
