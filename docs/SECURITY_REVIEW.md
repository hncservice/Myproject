# Security review — static and isolated evidence

This is a source review and synthetic regression record, not penetration testing or verification of deployed infrastructure. No actual environment secrets or production records were read. No dependency advisory service was contacted, so there is no claim that installed packages are vulnerability-free.

Backend isolation uses independent child processes, empty inherited environment, Node permission restrictions and deny-by-default CJS/ESM hooks plus runtime capability blockers. VM service code sees explicit synthetic dependencies and values only. Guards are reviewed test infrastructure, not a security sandbox for arbitrary hostile JavaScript; execute only the fixed reviewed scripts/cases.

Observed latency simulation (10:59 UTC repeat): at a simulated 200 ms one-way arrival delay, 60.3% of mathematically exact-center clicks were scored as misses; at 500 ms, 93.8%. Results are randomized modeling, not production latency measurements. This is a fairness/design risk requiring separately reviewed scoring/latency strategy; insecure timestamp compensation remains off.

## Phase D security evidence and limits
All seven adminController write transaction callbacks claim the active/role/version account fence. Vendor/prize creation is audited transactionally. Vendor activation/password/explicit revocation increments tokenVersion; role/disabled/revoked negatives use actual signed JWTs with fake models. Reports have strict limits, own-vendor scope or global authAdmin, explicit private serializers, spreadsheet formula/control sanitation and pre/post-query row caps. Review is manual, campaign/qualified-game scoped, conditional and audited; allocation/draw remain false. Four new read endpoints are after global authAdmin. Active mock graph, hardcoded allocation false and experimental endpoint non-registration are unchanged.

Real DB atomicity/rollback/indexes/multi-instance revocation, HTTP permissions and load are unverified. Vendor/prize creation now requires transaction support; existing prizeReviewFence is reused without schema/backfill. Existing raw error logging outside this targeted work remains a hardening gap. No service HTTP/SMTP/DB/customer data/real QR/operational script ran. Behavioral V1 is explicitly absent in review evidence rather than inferred from Integrity V2.

## Phase E security review
Four new campaign routes follow existing global authAdmin; no public campaign admission or experimental reporting route. Mutation actor/version is middleware-owned; server validates strict fields, UTC real-date ordering, supported registry games, fixed verification/prior-winner/concurrency restrictions, bounded attempts/prize IDs and active inventory references. Current legacy ID is reserved. Prototype/getter/unknown/allocation fields reject. Version CAS and canonical latest-request fingerprint prevent duplicate mutation/audit and stale overwrite; existing administrator fence/audit transaction reused. Campaign enabled is desired availability only: hardcoded release gate false, definitions disconnected from existing game start/status/engine, prize allocation flag unchanged.

Review uses existing authorized detail endpoint and server-owned scoped gameplay, reusing registered assessors independently. V1 remains enforcementAllowed:false and behaviorAffectsPrizeDecision:false. Original stored integrity finding/version and current recomputation are distinct; no combined score or automatic decision. Missing/oversized/incompatible evidence is explicitly unavailable. No raw game state/events/contact/credentials returned. Existing authorized manual decision audit retained.

Offline verification: 256 cases, signed wrong-role/revoked negatives retained; 354 frontend tests; 129 assessment assertions; 174 syntax checks. No real DB/HTTP/SMTP/server/data/prize action. Latest-key deduplication is not unlimited historical receipts. Immutable audit declarations/fake rollback are not proof of database immutability/atomicity. Real casting/index/transaction/role/concurrent config/revocation and inventory association tests need separate authorization. Assessor recomputation is not a historical evidence snapshot; registry-version resolution and evidence-to-review binding require future review. Full device/accessibility/cross-tab/session-expiry behavior and other raw-error logging remain open.
